# v1.0.7 运行期间应用索引刷新

## 问题与修复

原生版仅在启动时扫描一次开始菜单、桌面及打包应用。启动器保持托盘常驻后，
新安装应用的快捷方式无法进入搜索索引，直到进程重启。

本机排查确认启动器启动时间早于目标应用快捷方式的创建时间，快捷方式的目标
EXE 及工作目录均有效。搜索到名称相近的旧应用并不表示新应用已被索引。

修复复用完整的后台扫描、命令生成及去重路径，在以下时机执行：

- 启动时扫描。
- 重新唤出启动器时扫描；完成后 30 秒内的连续唤出不重复扫描。
- 每 30 分钟自动扫描，对齐 TS `apps/desktop/src/main/index.ts` 的
  `refreshIntervalMs: 30 * 60 * 1000`。

所有入口共用在途标记，对齐 `packages/core/src/indexer/appIndexer.ts` 的
`refreshInFlight`。扫描不阻塞 UI，结果回到 UI 线程后整体替换应用命令，重查当前
查询。收藏、系统命令和其他命令组不受替换影响；索引未变化时不重绘搜索结果，
避免重置结果选择。

## 回归验证

- 刷新调度覆盖首次扫描、冷却边界、周期刷新及慢扫描期间的重复请求。
- 实际创建 Windows COM 快捷方式，模拟运行期间安装和移除应用，验证后续扫描
  更新搜索结果、相近名称应用并存，以及桌面与开始菜单重复快捷方式合并。
- 搜索管线验证新增应用可检索、删除应用被移除、相同快照无需更新，且收藏和
  系统命令仍存在。模糊搜索允许返回相近结果，断言针对目标应用本身。
- `cargo test --workspace --quiet`：671 通过，4 个显式本机/外网探针默认忽略。
- 显式运行 `installed_app_is_searchable`：本机目标应用精确匹配排第一，桌面与
  开始菜单重复项合并为一条，且解析出的目标 EXE 存在。
- `cargo clippy --workspace -- -D warnings` 及 `cargo fmt --all -- --check` 通过。
  当前 stable 工具链的新增 Clippy 规则要求固定宽度像素分组改用 `as_chunks`；
  JPEG 去除 alpha 和 BGRA 转换两处做了等价替换，其他格式调整由 rustfmt 生成。

原生窗口的人工键鼠验收不包含在上述自动化测试结论内。
